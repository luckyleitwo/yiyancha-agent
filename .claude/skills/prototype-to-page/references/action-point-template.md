# 页面行动点模板

> 配合 [原型转写 Skill](../SKILL.md) 和 [页面系分模板](page-analysis-template.md) 使用。本模板不表示任何行动点已存在或已实现。

## 1. 收集检查表

- [ ] 主页面：按钮、链接、整行点击、搜索、筛选、排序、分页、Tab、折叠区。
- [ ] 条件入口：因状态、权限、数量或关联记录而显示 / 禁用的操作。
- [ ] 弹窗与抽屉：打开入口、字段、内部按钮、关联记录、提交与关闭。
- [ ] 关闭途径：右上关闭、底部关闭、取消、遮罩、Esc、返回上层或直接返回原页。
- [ ] 键盘与上下文：焦点进入、Tab 范围、关闭后焦点、滚动及筛选保留。
- [ ] 写操作：确认、防重、服务端状态校验、成功联动、失败、取消和审计。
- [ ] 展示区域：明确哪些卡片、标签、徽标、图例、说明、时间线不接受点击。

只看到截图时不能将隐藏操作勾为已核实；未经授权不在真实环境执行写操作。

## 2. 编号与分类

编号在同一份系分内保持唯一并稳定，可采用：

- `Axx`：主页面入口与查询操作。
- `Dxx`：详情 / 抽屉内操作。
- `Cxx`：确认、提交与写操作。
- `Rxx`：条件选择等独立弹窗操作。

编号不代表分类必须齐全；没有对应交互就不创建空条目。多个浮层使用额外前缀或连续编号，避免同名编号指向不同操作。

## 3. 行动点总表

| 编号 | 区域与入口 | 触发 / 显示 / 可用条件 | 类型 | 具体用途与行为 | 目标 ID / 参数 | 接口与证据 | 关联验收 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 待填写 | 名称、位置、整行还是按钮 | 状态、权限、数据条件分开写 | 路由 / 抽屉 / 弹窗 / 查询 / 写入 / 关闭 | 不只写“打开详情”或“提交” | 稳定业务 ID，不用数组序号 | I / E 编号；未知标记 | V 编号 |

每一项都要能回答：**谁在什么条件下，点击哪里，用哪个对象，做什么，结果是什么。**

## 4. 关键行动点详细说明

对写操作、跨页跳转、复杂详情等逐项填写；简单且规则相同的操作可以明确引用同一规则，避免重复抄写。

### <编号>：<行动点名称>

| 项目           | 要求                                            |
| -------------- | ----------------------------------------------- |
| 入口与触发方式 | 具体控件、行或键盘行为                          |
| 前置条件       | 是否显示、是否禁用、权限、业务状态、关联记录    |
| 输入           | 当前记录 ID、query/body、用户输入及来源         |
| 接口           | 已核实协议或明确的开发 Mock 约定                |
| 正常流程       | 从触发到结果的具体步骤                          |
| 成功结果       | 路由、关闭、提示、刷新对象与状态联动            |
| 取消结果       | 是否关闭、回到哪里、不得发生哪些请求或状态变化  |
| 失败结果       | 错误呈现位置、保留哪些输入 / 上下文、可重试条件 |
| 防重与竞态     | 连击、切换记录、旧请求回写、重复提交与状态冲突  |
| 焦点与滚动     | 焦点进入 / 回归、Tab 范围、滚动锁定及恢复       |
| 证据与确认状态 | 原型实际行为、源码、接口文档或用户决定          |

## 5. 路由跳转专用检查

| 入口编号 | 原型目标 | 目标项目路由 | 参数与编码 | 菜单选中 | 筛选 / 页码规则 | 目标页现状与本轮边界 |
| --- | --- | --- | --- | --- | --- | --- |
| 待填写 | 实际链接或事件结果 | 已存在 / 待确认，不能捏造可用页面 | 确切业务 ID 和参数 | 对应菜单 | 是否保留或重置，以证据为准 | 不自动开发目标模块 |

不能把路由跳转改成业务预览抽屉；原型没有的自动筛选、返回层级、卡片跳转不能擅自增加。目标页缺失时记录依赖，不用占位页假装完成。

## 6. 浮层专用检查

每个弹窗或抽屉必须说明：

- 标题、副标题、宽度、主体分区、字段、业务关联、底部按钮与滚动范围。
- 内部操作各自的目标和 ID，不能只总结外部打开入口。
- 打开关联详情时：替换当前浮层、叠加，还是跳独立页面；以证据为准。
- 关闭 / 取消后：回原页面、恢复上一层，还是进入其他页面；不能自行增加返回栈。
- 右上关闭、底部关闭、遮罩、Esc 是否一致；提交中分别如何控制。
- 单关联、多关联、无关联、关联缺失、记录打开后失效的分支。

## 7. 写操作结果矩阵

| 场景 | 应发生的行为 | 不允许的行为 |
| --- | --- | --- |
| 仅打开确认 | 展示内容与待操作对象 | 提前发写请求 |
| 取消 / 关闭 | 按确认规则返回，不改变业务数据 | 发请求、改状态或新增业务操作日志 |
| 提交中 | loading、同步防重、约定的关闭限制 | 多笔重复写入或显示假成功 |
| 写入成功 | 按协议更新本记录、全部关联记录及审计，再处理查询刷新 | 只改提示文字，不更新真实 Mock / 服务状态 |
| 无权限 / 记录不存在 / 状态冲突 | 区分原因并反馈；状态校验由服务端执行 | 用前端按钮隐藏代替后端校验、操作其他记录兜底 |
| 写入失败 | 保留必要上下文并允许合理处理 | 伪造数据变化或成功提示 |
| 写入成功但刷新失败 | 告知实际结果，提供重新读取能力 | 误报写入失败，引导用户重复提交 |
| 网络结果不确定 | 引导查询核实当前状态，按协议处理重试 | 断言一定没有发生写入 |

未获准真实写入时，在隔离 Mock 中验证矩阵，并在交付报告中说明验证环境，不向业务页面塞开发状态说明。

## 8. 非行动区域

| 区域   | 展示用途                   | 不应增加的行为             | 依据   |
| ------ | -------------------------- | -------------------------- | ------ |
| 待填写 | 统计、说明、状态或时间记录 | 不自动加跳转、筛选、弹窗等 | E 编号 |
