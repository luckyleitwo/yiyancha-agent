# 页面组件选型模板

> 配合 [原型转写 Skill](../SKILL.md) 与 [页面系分模板](page-analysis-template.md) 使用。先检查现有能力，只有确有缺口才调研新库；本模板不授权安装依赖。

## 1. 项目基线

| 项目 | 实际版本 / 配置 | 核对位置与日期 |
| --- | --- | --- |
| 框架与构建器 | 从当前项目读取，不凭旧印象填写 | package.json、框架配置等 |
| React / TypeScript | 核对实际依赖与 peer 要求 | 项目依赖 / 锁文件 |
| 现有 UI 与业务组件库 | 核对声明、使用方式及主题 | 依赖与实际组件 |
| 现有封装 | 可直接复用的相关组件 | 真实文件位置 |
| 约束 | 浏览器、响应式、许可证、主题、包体积等 | 用户要求或项目依据 |

## 2. 页面能力对应表

| 页面区域 | 必须还原的能力与证据 | 现有组件 | 可行实现方式 | 确切缺口 | 是否需新库 |
| --- | --- | --- | --- | --- | --- |
| 待填写 | 视觉与交互，不只列组件名称 | 实际可用组件 | 直接复用 / 局部样式 / 自定义封装 | 未找到能力需说明原因 | 无需 / 待比较 |

判断顺序：现有组件 → 局部样式 → 有明确职责的自定义封装 → 第三方库。不能因为间距、颜色或布局不一样就直接换 UI 体系，也不能为避免选型静默删减原型行为。

没有新增组件库需求时，写明结论即可，不为凑模板推荐无关库。

## 3. 候选库调研

通常提供 2 ～ 3 个实际可行的方案。只有一个可行方案或无法检索时如实说明，不伪造候选和验证结果。

| 比较项 | 方案 A | 方案 B | 方案 C（确有必要时） |
| --- | --- | --- | --- |
| 库 / 组件名称与核对版本 | 待填写 | 待填写 | 待填写 |
| 对应的具体缺口 | 待填写 | 待填写 | 待填写 |
| 原型还原程度与差异 | 待填写 | 待填写 | 待填写 |
| React / 框架 / TypeScript 兼容性 | 说明实际版本要求及依据 | 同左 | 同左 |
| 与现有 UI / 主题 / Less 的关系 | 样式隔离、主题接入、冲突风险 | 同左 | 同左 |
| 键盘、焦点与可访问性 | 实际能力与已知限制 | 同左 | 同左 |
| 维护情况 | 发版、维护说明、归档或弃用情况 | 同左 | 同左 |
| 许可证与使用限制 | 准确名称与限制，未知须标记 | 同左 | 同左 |
| 包体积与加载影响 | 标明测量 / 官方数据 / 未测，说明口径 | 同左 | 同左 |
| 接入与后续维护成本 | 依赖、封装、样式、升级等具体工作 | 同左 | 同左 |
| 官方文档与维护仓库 | 实际查阅的 URL | 同左 | 同左 |
| 核对日期与验证深度 | 文档核对 / 最小验证 / 浏览器验证 | 同左 | 同左 |
| 未验证事项 | 不以推断冒充已验证 | 同左 | 同左 |

优先查官方文档、发布说明、包信息和维护仓库；推广文章不能替代兼容性与许可证依据。不在未经许可的情况下安装候选库以“先试再说”。

## 4. 推荐与用户选择

### 推荐方案

- 推荐哪个方案，以及它怎样满足当前缺口。
- 与其他方案相比的关键取舍。
- 无法完全复现的部分及其影响；不能隐瞒删减。
- 如有必要，提供能比较实际差异的官方效果链接、截图、结构示例或交互说明，注明来源与验证情况。

### 用户选择记录

| 决策 | 当前状态 |
| --- | --- |
| 用户选择的方案 | 待选择，未确认不能代填 |
| 用户实际确认依据与日期 | 待填写 |
| 获准新增的依赖与用途 | 只记录明确同意的部分 |
| 获准的交互 / 样式差异 | 无变化则写无；重大差异需确认 |
| 未选择前的实施边界 | 不安装、不换库、不改变交互；可继续不依赖选型的分析工作 |

现有组件和常规局部样式已能满足时，执行者按项目规范判断，不要求用户决定每个小样式细节。

## 5. 确认后的验收要求

- [ ] 锁定实际所需依赖范围，不附带无关升级或第二套全站 UI。
- [ ] 使用项目组件目录规范封装，不把第三方用法散落到多个页面。
- [ ] 验证样式隔离、主题、键盘与焦点、所需屏幕尺寸、加载及异常场景。
- [ ] 逐项核对原型要求，未实现部分如实记录，不用开发说明文案或占位组件替代。
- [ ] 系分记录最终选型及差异，交付说明验证结果；不把文档核对写成浏览器验证通过。
